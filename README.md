# jyotish-map

Система разбора карты Джйотиш: методика из десяти промптов плюс код, который
берёт на себя то, что не должна делать языковая модель.

Репозиторий устроен как **маркетплейс плагинов Claude Code** с одним плагином
внутри:

```
.claude-plugin/marketplace.json    манифест маркетплейса
plugins/jyotish/
├── prompts/                       методика: 00_README и промпты 01…10
├── templates/                     шаблон вёрстки клиентского PDF
├── skills/jyotish-reading/        скилл, ведущий разбор по этапам
├── commands/                      команды /jyotish:*
├── jyotish/                       код: сбор, расчёты, проверки
└── tests/
ARCHITECTURE.md                    что автоматизируется, что остаётся человеку
```

Методика в `prompts/` — единственный источник правды о том, как ведётся разбор.
Код не заменяет её, а исполняет ту часть, которую нельзя доверять языковой
модели.

## Установка

Как плагин Claude Code:

```
/plugin marketplace add serg123e/jyotish-map
/plugin install jyotish@jyotish-map
```

Появятся команды `/jyotish:new`, `/jyotish:collect`, `/jyotish:stage`,
`/jyotish:soul-path`, `/jyotish:check`, `/jyotish:status` и скилл, который
ведёт разбор по этапам и не даёт проскочить гейты.

Больше ничего ставить не нужно: команды зовут CLI через launcher
`bin/jyotish`, который при первом обращении сам поднимает изолированный venv в
каталоге данных плагина. Первый вызов ~15 секунд, дальше мгновенно, системный
Python не трогается.

Для работы из терминала без Claude Code:

```sh
pip install -e plugins/jyotish     # или просто plugins/jyotish/bin/jyotish
```

Данные берутся с [vedic-horo](https://vedic-horo.com) через
[`vedic-parser`](https://github.com/serg123e/vedic-parser). Астрономических
расчётов здесь нет и не будет: положения планет, куспиды и даты даш приходят с
сайта как есть.

## Этап 01: сбор данных

```sh
jyotish new ivan                  # создаст clients/ivan/chart.yaml
$EDITOR clients/ivan/chart.yaml   # дата, время, координаты, статус времени рождения
jyotish collect clients/ivan      # ~97 запросов к сайту, с кэшем
jyotish status clients/ivan       # что собрано, что осталось
```

Координаты — **градусы и минуты**, не десятичные: `55.45` значит 55°45′,
ровно как отправляет форма сайта. Отрицательные для юга и запада.

На выходе три файла:

| Файл | Что это |
|---|---|
| `01_RAW_DATA.md` | полный технический экспорт по 19 разделам Промпта 01 |
| `01_MISSING_DATA.md` | чего нет и почему, маркерами из Промпта 01 |
| `state/summaries/01.md` | сводка для этапа 02 — вместо ручного копипаста |

### Про запросы к сайту

Каждый запрос заставляет сайт считать карту, поэтому ответы кэшируются в
`clients/<slug>/raw/` и между вызовами выдерживается пауза (`collect.throttle`,
по умолчанию 2 с). На сплошном проходе сайт всё равно может ответить `429` — тогда
сбор останавливается с внятным сообщением, а уже полученное остаётся в кэше:
повторный запуск продолжит с того же места. `--refresh` пересобирает всё заново.

Кэш привязан к параметрам карты. Если время рождения ректифицировали, старые
ответы не подмешаются: сборщик откажется работать и попросит `--refresh`.

## Этап 07: пройденность пути души

Промпт 07 запрещает назначать итоговое число «по общему впечатлению». Поэтому
модель выставляет только шесть баллов слоёв — **с обоснованием каждого**, — а
взвешенную сумму, подшкалы и таблицу вкладов считает код.

```sh
jyotish soul-path clients/ivan --template   # заготовка soul_path_input.json
jyotish soul-path clients/ivan              # посчитать, записать главу
```

Этап отказывается работать, а не выдаёт число послабее, когда:

* время рождения не подтверждено и не ректифицировано — гейт самого Промпта 07;
* нет данных D60, на который приходится 30% веса;
* у слоя выставлен балл без обоснования — это и есть «общее впечатление» с цифрой.

Отсутствие D20 — единственное послабление, которое промпт разрешает: его 10%
делятся между D1 и D9, и это печатается в главе, а не остаётся догадкой.

## Этап 10: чек-лист качества

```sh
jyotish check clients/ivan       # пишет qa.md, ненулевой код возврата при провалах
```

Из 27 пунктов Промпта 10 код решает 13: три шкалы не перепутаны, таблица слоёв
на месте, оговорка про 0% есть, гейт 07 соблюдён, камни идут после таблицы
функциональных ролей, приоритет медицины назван, доля терминологии в пределах
20%, у каждого паттерна ≥3 подтверждения из разных слоёв.

Остальные 14 требуют смысла и помечаются **«нужен читатель»** — не «пройдено».
Чек-лист, который тихо пропускает половину пунктов, хуже, чем его отсутствие.

## Что считает код, а не модель

Прямо в `plugins/jyotish/jyotish/derive.py`, потому что у этих величин один правильный ответ:

* **арудха-пады** A1–A12, AL, UL, Дара-пада — сайт их не отдаёт;
* **диспозиторы** и паривартана;
* **чара-караки** по наибольшему градусу — и сверка с тем, что показывает сайт.
  Неверная Атмакарака названа в методике как повторяющаяся ошибка, поэтому она
  считается независимо, а расхождение печатается блоком `РАСХОЖДЕНИЕ`, а не
  разрешается молча;
* **сила домов** — три показателя на дом: бинду САВ, шадбала управителя и
  дришти на дом.

Всё вычисленное здесь помечено в экспорте как **[расчёт]** — читатель должен
отличать нашу арифметику от данных сайта.

## Тесты

```sh
cd plugins/jyotish && python -m pytest
```

Офлайн: фикстуры в `plugins/jyotish/tests/fixtures/`, сеть не нужна.

## Границы

Варшапхала и транзиты закрыты платным доступом. Всё это попадает в
`01_MISSING_DATA.md` с причиной, а не заполняется догадкой.

**Бхава-балы нет и она не реконструируется.** Бхавадхипати-бала доступна
напрямую, но Бхава-Диг-бала требует классической таблицы, а формулу
Бхава-Дришти-балы воспроизвести не удалось: собственная дрик-бала планет у
сайта не выводится из его же матрицы аспектов. Собранное наполовину по памяти
число выглядело бы точным и не было бы проверяемым. Поэтому — три показателя,
каждый прослеживается до цифры сайта, и они намеренно не складываются.
